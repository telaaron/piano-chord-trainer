# iOS Build 4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Beginner-friendly Heute, one central Settings + account page, one icon system on Üben, website guides in Lernen, and login with cross-device sync shared with the web.

**Architecture:** Pure, tested logic (TodayStage, PlanPresentation, SyncMerge, SyncKeys) sits in small app files; views consume it. Auth uses supabase-swift; a `SyncService` owns hydrate/upload with the web's "no upload before hydrate" guard, behind a `RemoteUserData` protocol so tests use a fake. `Store.save` reports each saved key so sync marks itself dirty.

**Tech Stack:** SwiftUI iOS 17, Swift 6, xcodegen, MusicEngine SPM, supabase-swift ≥ 2.0 (product `Supabase`), SvelteKit + vitest on the web.

**Spec:** docs/superpowers/specs/2026-10-16-ios-beginner-login-design.md

## Global Constraints

- iOS 17.0 deployment target; Swift 6 strict concurrency; views stay `@MainActor`, pure helpers `nonisolated static` so XCTest can call them.
- Bundle id `app.jazzchords.trainer`; Supabase project `https://chpoqghvlojwyunoplab.supabase.co`, publishable key = `TelemetryService.Config.anonKey` (move to a shared `SupabaseConfig`).
- Every user-facing string goes through `Strings` (`pick(en, de)`) or `CoachL10n`; German copy exactly as in the spec / row F mockups.
- Chord symbols (Δ7, 7, –7, 1·3·7, R, ∞, +) are never used as icons.
- Sync keys and merge rules are byte-compatible with web `cloud-merge.ts` / `cloud-sync.ts`.
- CURRENT_PROJECT_VERSION "4", MARKETING_VERSION stays "1.0.0".
- Tests run only on Aaron's Mac: `xcodebuild test -scheme JazzChords -destination 'platform=iOS Simulator,name=iPhone 17'` and `swift test` in `ios/MusicEngine`. Web: `npm test`.

## Review Focus

- Signed in on two devices, both practiced offline, then both come online: no session may be lost (union by id) — pinned in Task 2 `testTwoOfflineDevicesUnion`.
- Sign-in fails mid-hydrate (network drop): device data must stay untouched and nothing is uploaded — Task 4 `testFailedHydrateNeverUploads`.
- A web-only key (`chord-trainer-celebrations`, `-theme`, `-locale`) must survive an iOS upload — Task 3 `testUnknownWebKeysSurviveUpload`.
- User switches account (sign out A, sign in B): B must not receive A's upload — Task 4 `testSignOutResetsHydration`.
- Newcomer guide must not reappear after the × even if history is cleared — Task 6 `testDismissIsPermanent`.
